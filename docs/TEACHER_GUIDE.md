# 教师指南与参考答案

本指南配合[学生操作手册](MANUAL.md)。目标是让学生亲手体验科学知识记录的建立、关联、检查和修订，不考核大模型训练或湿实验操作，也不要求每人购买 API。

## 1. 备课与教学边界

固定必做案例为 Organic Syntheses DOI `10.15227/orgsyn.102.0114`。其公开文本、作者仓库真实结果、课程来源参考分别承担不同角色：原文用于取证，上游结果用于重现可观察的抽取局限，课程参考用于有限范围自动比较。

参考记录由助手逐项对照公开原文建立，标记 `source_checked`。它不是原作者发布的 gold，也不是独立化学专家评审。建议教师在正式评分前复核两轮结果、字段含义与证据位置；不要把参考文件存在当作免于来源审查的理由。

本仓库的真实方法边界：

| 部分 | 实现性质 |
|---|---|
| 固定 ReactionSeek 提示词、公开输出 | 上游材料；固定 commit 和哈希 |
| DeepSeek HTTP 调用、预算与结果保存 | 课程模型适配，非重现原 GLM 数值指标 |
| 四实体缓存、名称规范化、单位规则 | 借鉴标准化思路的有限案例实现，非任意实体自动消歧算法 |
| ORD 序列化及规则诊断 | 调用实际 `ord-schema==0.9.6` |
| SQLite、独立实验身份、参考对比、patch、历史与查询 | 课程新增实现 |
| RXN Filter | 独立选做的结构合理性筛查，不作为事实真伪判据 |

不要把各环节描述成“直接复现三篇最新顶刊的完整系统”。更准确的课程表述是：**固定论文材料与方法复现，加上明确标注的教学集成，实现一条可检查的知识建模流程。**

## 2. 上课前验收

按学生手册建立全新的 Python 3.12 环境，安装运行锁文件、开发锁文件与本包。在新目录执行：

```bash
python -m reaction_knowledge_lab fetch
python -m reaction_knowledge_lab check-evidence
python -m reaction_knowledge_lab demo --workdir runs/teacher-check
python -m reaction_knowledge_lab verify --workdir runs/teacher-check
python -m pytest -q
python scripts/run_notebooks.py
```

预期：证据检查 `verified`、13 个定位；demo 15 项检查全真，`api_calls: 0`；测试和 Notebook 无失败。若 `runs/teacher-check` 已有结果，使用 `verify` 或换新目录。

`verify` 会检查 demo 专用结构并再次应用同一 patch 来证明幂等；不适用于任意手工命名目录。缺原文时回放可以完成，但 `evidence_check` 为 `not_checked`，证据相关 pytest 会跳过。请在评分时区分“离线流程完成”和“重新核对来源完成”。

当前真实 API 实测仅一次、一个文献过程：2026-11-10，DeepSeek Flash，7279 输入和 113 输出 tokens，按核价时高峰未缓存价格估算 0.015462 元。元信息见 [`data/replay/deepseek_20261110.metadata.json`](../data/replay/deepseek_20261110.metadata.json)。不把该估值当账单实扣，不把一次结果外推为批量准确率。

## 3. 建议的教学顺序

1. **先看原文和原始结果。**让学生圈出源文中“第二次实验”的报告，比较上游 CSV；不要先给他们修正后的 JSON。
2. **建立身份层次。**明确化合物实体、实验记录、一次测量和一条来源之间不是同一概念。运行别名解析，观察实体 ID 相同而实验 ID 可以不同。
3. **分别看两个检查报告。**让学生解释为什么 ORD 能通过部分检查，而来源对照仍报缺漏。
4. **注入明确标记的教学错误。**将 72% 改为 27%，观察产率阈值查询变化；必须承认是课程故意注入。
5. **逐项审查修订提案。**学生说明每项修改依据，尤其为什么 R2 不复制 R1 条件；然后应用 patch。
6. **证明更新不是覆盖。**观察三个历史版本、同 patch 重放无新版本、旧查询文件保持历史快照而重新查询得到新结果。
7. **再做模型或更多资料扩展。**有 API 的学生可实调，其余学生使用公开缓存；统一评价后续建模能力，而非是否付费。

## 4. 必做案例参考答案

### 4.1 两个实验为什么不能合并

原文明确报告两次实验。第一轮 benzophenone 质量 2.63 g、产率 72%、qNMR 纯度 99.8%；第二轮质量 2.62 g、产率 72%、纯度 98.6%。共用产物身份 `pubchem:3102` 不构成同一次实验的证据。

最终 `record_id` 分别是：

- `orgsyn-102-0114-run-1`
- `orgsyn-102-0114-run-2`

R2 的 `raw_record_id` 是 `manual-reference:` 前缀的课程标识，表明它是依据原文补录，不冒充模型已输出的行。

### 4.2 第二轮哪些字段应为空

第二轮结果句没有逐项重述投料、溶剂、时间和温度。参考保持：

```json
{
  "inputs": [],
  "solvents": [],
  "conditions": {
    "raw_time": null,
    "time_minutes": null,
    "raw_temperature": null,
    "temperature_c": null
  }
}
```

相同 `source_id` 允许回到同一 procedure，不代表课程可以把 R1 的条件声明为 R2 逐项直接报告事实。若未来需要表达“按相同程序重复”的推断，应单独建模推断关系及依据；不能静默填入当前字段。

### 4.3 名称归一的参考答案

| 名称或别名 | entity_id |
|---|---|
| 1,1-diphenylethene；1,1-diphenylethylene | `pubchem:10740` |
| 4-nitrobenzonitrile | `pubchem:12090` |
| acetonitrile；CH3CN | `pubchem:6342` |
| benzophenone；diphenylmethanone | `pubchem:3102` |

36 h 换算为 2160 min；30–35°C 保留两个端点，不取平均。未知名称保持 unresolved。不能把泛指的一类化合物选成任意具体成员。

### 4.4 为什么 27% 没有被 ORD 自动判成来源错误

27% 是合法范围中的数值；ORD 无法仅靠这个数值知道论文实际报告了 72%。课程来源参考比较才会标出 `source_mismatch`。因此：

| 时点 | 当前知识记录数 | 产率≥70%查询条数 | R1当前版本/产率 |
|---|---:|---:|---|
| 初始导入 | 1 | 1 | v1 / 72% |
| 注入教学错误后 | 1 | 0 | v2 / 27% |
| 来源修订后 | 2 | 2 | v3 / 72% |

R1 的历史应有三个版本，R2 新增时是 v1。原始 `raw.Yield` 始终保留 `72%`，证明原输出没有被当前值覆盖。

### 4.5 为什么最终知识库有两条，ORD完整子集只有一条

有来源支持的不完整实验观察仍有知识价值，所以两轮都进入知识库。ORD 对完整反应输入有要求；R2 缺少输入物质，因此不能进入没有 ORD errors 的子集。这个分离是预期教学结果，不是失败后应该补造字段的理由。

即使 R1 进入 `ord_structurally_ready.json`，仍可能有 warnings，也不代表适合任意训练任务。该课程最小字段未完整结构化照射、气氛等条件，不能作为湿实验复现的充分记录。

### 4.6 如何证明修订可追溯与幂等

历史记录应含旧记录、当前版本号、修改原因、依据、patch ID 和时间。同一份 patch 再应用返回 `already_applied`；R1 历史仍为三版。相同 patch ID 但不同内容、过期 expected_revision 或无依据的 patch 应被拒绝。

来源修订提案由现成课程参考生成，不应称为自主文献核验模型。数据库检查依据字段存在，不自动保证每条依据在科学意义上都支持修改；因此需要学生阅读提案。

## 5. 学生活动与评分建议

可采用以下 100 分框架，也可按教学安排调整。

| 项目 | 分值 | 证据 |
|---|---:|---|
| 环境、固定数据与来源 | 15 | 依赖版本、文件哈希、模式说明；使用了哪条抽取路径 |
| 抽取结果分析 | 15 | 找出第二轮漏抽，区分真实错误与教学注入 |
| 实体与记录身份 | 20 | 别名映射正确，两个实验独立，原值未丢失 |
| 校验解释 | 20 | 区分 ORD、参考比较和原文证据；解释27%例子及R2不完整 |
| 修订、查询与历史 | 20 | 1→0→2查询、72→27→72历史、重放无重复版本 |
| 范围与局限 | 10 | 未把参考称专家gold，未将离线回放冒称API调用或全论文复现 |

只交一张 `passed: true` 截图不足以证明理解。建议至少抽查：原文位置、一个 mapping 条目、一个 patch 的依据、历史中的两个版本，以及对 R2 空字段的解释。

不因学生没有 API 扣分。实调者与缓存回放者均需证明来源和处理步骤；实调者另外报告 model、usage、prompt hash、结果差异及费用估算，不能上传密钥。

## 6. 扩展题参考方向

### 五篇上游样例为什么六行不等于六条正确实验记录

总共有五篇原文。`volume102article22` 的第二轮漏掉；`volume102article24` 的分离馏分和总产率又被拆成两行。它们可能在数量上抵消，所以只对总数不能发现错误。

`volume102article24`：第一行含两批分离结果 65% 与 8%，第二行给出合并 73%。它们属于同一反应，不应当作两个独立实验；不同结果测量或分离馏分可以作为同一实验的多个观察。

`volume102article28`：后处理的 acetone 与 1 h 被放入反应字段。应区分阶段，再建立溶剂、时间和阶段之间的对应，不能直接将多个数字相加。

`volume102article17`：40°C 12 h 后升至75°C并继续6 h。更适合用有顺序的条件阶段列表，而不是用最高温度和总时长替代整个程序。

`volume102article9`：标题与部分正文名称对 `6-methoxy` 的表述不一致；本课程不自动消除这一疑点。可以要求学生说明还需要查看哪些结构图、表征或补充材料。

### 比较 GLM 回放与 DeepSeek 实测

已发布的那次 DeepSeek 结果只有35°C，原GLM示例为30–35°C；两者都漏掉第二轮。模型替换会改变误差分布，不能根据一次样例建立稳定排名。可比较字段级差异，但不能把只有一篇的结果包装成模型准确率结论。

## 7. 教师排查要点

- 检查学生是否混用了 `runs/demo` 与 `runs/manual`；`verify` 只接受 demo 结构。
- 检查是否误把 summary CSV 的空占位行算成一条模型回答；实际是5个非空回答。
- 检查是否为了得到全通过而删除R2、把null填0、或复制R1输入；这些会损害科学保真。
- 检查是否把旧查询快照“没有自动变化”当成更新失败；本课程要求重新查询，旧文件用于保留前后对照。
- 检查真实调用失败后是否重复付费；本程序不自动重试，元信息已有状态时应先看原因。
- 评分时以实际生成的检查报告为证据，不把Windows/Linux命令或CI配置视为所有平台已经完成实测。

若需要扩大案例，应先补该领域的记录粒度、实体缓存和来源参考，再设计评价。现有四实体缓存和一篇参考的边界清楚，便于学生看懂；不能将其成功运行外推到任意科学知识库。
